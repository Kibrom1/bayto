`bayto-dev`, task_id `wad-102`) launched by `dev-team/run.sh`, which installs

i.e. this session's coordinator/developer exchange ran the real workshop
`crew`/`handoff` CLI surface with the acp shim standing in for the reference
bash `handoff`, not a synthetic harness.

`tests/test_handoff_compat.py` runs every case against both
`vendor/wad-sbx-workshop/chapters/support/bin/handoff` (bash reference,
needs `jq`, present in this sandbox) and `handoff_compat.py` (acp shim):

documented divergence in the shim's favor, not a regression.

## 2. Real end-to-end run: exact live sequence replayed against both implementations

The live factory at `~/work/factory` (this session) was driven through the
real `crew ask` → `handoff send` → `crew-notify` (claim) → `handoff read`
path for two real messages:

1. `human` → `coordinator`, kind `question` (the M1.5 assignment)
2. `coordinator` → `developer`, kind `note` (task handed to this developer)

`scripts` (scratch, not committed): replayed the identical sequence of
`handoff init` / `send` / `claim` / `read` calls — same run id, task id,
message bodies — once against the bash reference and once against the acp
shim, each in its own isolated `$FACTORY_DIR`.

Results:

- **Directory layout**: identical, path-for-path, after normalizing the
  random suffix in message ids (`messages/`, `claims/`, `consumed/`,
  `ready/`, `state.json`).
- **Message JSON**: byte-identical after normalizing `message_id` and
  `created_at` (schema, field order via `jq -S`, `refs`, `requires_ack`,
  `attempt`, `seq`, `from`/`to`/`kind`/`body` all match).
- **`state.json`**: identical after normalizing timestamps (`run_id`,
  `task_id`, `attempt`, `stage`, `seq`).
- **Live factory vs. replayed reference**: the two messages actually
  produced by the *live* session (`~/work/factory/messages/*0001*.json`,
  `*0002*.json` — real acp-shim output, not a replay) diff to nothing
  against the bash reference's replayed output for the same operations,
  after the same normalization. This is the direct proof that the live
  run's on-disk behavior matches what the reference `handoff` would have
  produced for the same inputs.

One cosmetic, non-contractual difference: the random suffix in
`msg-<run>-<seq>-<rand>` is 6 chars from the shim's `rand6()` vs. 10 chars
from the bash reference's `rand()`. Neither the protocol doc nor
`test_handoff_compat.py` pins a suffix length (only the `msg-<run>-<seq>-`
prefix and overall uniqueness are asserted), so this is not a behavior
change.

## Conclusion

No behavior change: same CLI surface, same exit codes, same on-disk
`$FACTORY_DIR` schema, same real messages for the same real operations.
M1.5 is done.
