Bayto architecture

A local-first app where several AI agents take turns on one task. A web page talks to one orchestrator; the orchestrator decides who speaks, builds each agent's prompt, sends the turn to a model, and records everything in Postgres.

Design choices worth knowing

Local first, no accounts

One orchestrator, one Postgres, your own Claude login. Sign-in is an optional shared token for when the port is reachable by others.

Context is chosen per seat

Each seat gets the excerpts most relevant to its role and the current question, filtered by who may see each attachment, within a fixed budget.

Everything is recorded

Messages, usage, stop reasons, fallbacks and exports are stored and audited, so a session can be exported as a decision record.

Changes need a person

Build never pushes or merges. Output is a branch, a change set and a pull request that you open.
