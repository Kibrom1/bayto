# Bayto UX review, 2026-10-23

Scope: landing, task board (search, empty state, New task dialog), session setup (all four modes, roster, model pickers, budget warning, Create agent dialog, Build repository panel), the room (running, paused, finished, interrupted, failed, Build with change set; confirm dialogs, Export, context rail, role picker), services, sign-in, 404 and missing-session states.
Method: real app with fakes (see docs/e2e/features/README.md), Playwright Chromium, 1280 and 390 px, light and dark, axe-core on each page at 1280 light. Screenshots are in /tmp/ux-review/ named `<page>-<width>-<scheme>.png`; not committed.
Caveats: transcript text is fixture text ("pm here: I take a position..."), so judgements are about layout and wording, not content. A few empty rosters and token counts on the Build session come from seeding it through SQL, so they are not listed as findings. axe found no color-contrast violations and only the issues in UX-14, UX-22 and UX-23.

Totals: P1 5, P2 14, P3 12 (31 findings). No P0.

## P1

**UX-01 Room, mobile: header actions overflow the viewport (horizontal page scroll)**
`room-paused-390-light.png`, `room-context-390-light.png`. At 390 px the action row (Resume, Export, End & synthesize, Archive, Delete) ends at x=427, so Delete is cut off and the whole page scrolls sideways. Same on finished, paused and failed rooms and behind every confirm dialog (`room-delete-confirm-390-light.png` shows the page shifted left).
Why: the one destructive action is half hidden, and sideways scroll on a chat page makes the transcript feel broken.
Fix: let the action row wrap (`flex-wrap`), or move secondary actions (Export, Archive, Delete) into a "More" menu on narrow screens, keeping the one primary action visible.

**UX-02 Room, finished: the result is hidden; the page opens scrolled to the bottom of the transcript**
`room-finished-1280-light.png` vs `room-finished-top-1280-light.png`. A finished session scrolls to the last turn, so the Final synthesis (the whole point of a Debate) is above the fold and the "Jump to latest" pill appears when you scroll up to find it. On first view the user sees turn 6 of a debate and a disabled composer.
Fix: on finished sessions with a synthesis or change set, open scrolled to the result (or pin a "Decision" summary strip above the transcript with "Read full synthesis"). Reserve auto-scroll-to-end for live sessions.

**UX-03 Room, failed and interrupted: the reason and the next step are buried**
`room-failed-1280-light.png`, `room-interrupted-1280-light.png`. A failed session says "Something went wrong while it was running." and hides the cause in a collapsed "Technical details" (for example "the provider rejected the API key"). The only way forward is the small "Start a new session" link in 12 px helper text under the disabled composer. The empty transcript says "Waiting for the first seat to speak..." on a session that will never speak.
Fix: show the human-readable cause in the banner, add a primary "Start a new session" (or "Retry with same team") button in the banner and header, and replace the empty-state copy for ended sessions with "No turns were recorded."

**UX-04 Room, ended states: disabled composer takes the primary slot**
All ended rooms (`room-finished-*`, `room-failed-*`, `room-build-*`). A full-width composer with a "To: Everyone" select, a greyed Send button and "This session has ended" stays at the bottom of every ended room, while the real next actions ("Start a new session") are tiny links. In dark mode the disabled Send is an amber-brown button that still looks clickable (`room-tall-context-dark.png`).
Fix: when ended, replace the composer with a one-line bar: "Session ended. [Start a new session] [Export]". Do not render a disabled form.

**UX-05 Room, mobile: the roster, context and usage are far below the transcript; no way to reach them**
`room-context-390-light.png`, `room-running-390-light.png`. On a phone the Context card (the only place to add files and set who can read them) sits after the roster graphic, 1,400 px below the composer. There is no tab bar, sticky link or "Context" button in the header. Users who join mid-session will not know attachments exist.
Fix: on narrow screens use a bottom sheet or tabs (Conversation / Team / Context / Usage), with a count badge on Context.

## P2

**UX-06 Room: no UI for muting, removing or adding a seat; no human seat**
`room-paused-1280-light.png`, `room-running-1280-light.png`. The API supports mute, unmute, remove and add participant, but the roster rows have no controls, and focus order (`Resume, Export, End, Archive, Delete, Conversation, Send to, Interject`) confirms nothing is hidden. The "Send to" menu is the only per-agent control.
Why: the "steer the table" promise has no way to quiet a seat that is derailing a debate or burning budget.
Fix: add a row menu (Mute, Remove, Change model) on each roster entry with a confirm for Remove, and an "Add agent" button in the roster header while the session is live or paused.

**UX-07 Room, finished: three overlapping export actions with no explanation**
`room-finished-1280-light.png`. The header has "Export" and "Download transcript", the banner has "Export decision record", and the synthesis card has "Copy Markdown" and "Download .md". The user cannot tell which file they will get. Feedback after Export is a small "Decision record downloaded" line inside the amber banner (`room-export-390-light.png`).
Fix: one "Export" menu with named options (Decision record .md, Full transcript, Copy Markdown), and a toast for the result. Remove the duplicate buttons.

**UX-08 Room, finished: amber "warning" banner for normal endings**
`room-finished-1280-light.png`, `room-build-1280-light.png`. "Session ended because it reached its round limit" and "because build complete" use the same warning amber as pause and failure. "Build complete" is a success shown as a caution.
Fix: neutral banner for normal endings, green for successful Build, amber only for limits that cut work short, and reword "because build complete" to "The build finished: tests passed and the reviewer approved."

**UX-09 Room: "Active", "Live" and "Round 1" repeat the same state; breadcrumb says "Bayto room"**
`room-running-1280-light.png`. The status chip and a separate "Live" dot say the same thing, and the breadcrumb "Tasks / Bayto room" names the product, not the task. The cost line "$0.01 of $5.00" has no label.
Fix: drop the extra "Live" dot, make the breadcrumb "Tasks / <task title>", label cost ("Spent $0.01 of $5.00 cap").

**UX-10 Room: attachment list is a clipped scroll box; audience control looks like body text**
`room-context-1280-light.png`. The attachments list is a short fixed-height inner scroll area that cuts the third item in half, inside a rail that is itself scrolling. "Everyone" and "Only ux-designer" are underlined links sitting beside "Remove" and read as labels; nothing says clicking them changes who can read the file. Two files with the same name are allowed with no warning.
Fix: let the list grow, show audience as a labelled chip ("Visible to: everyone / UX Designer only") with a lock icon for restricted items, and flag duplicate names.

**UX-11 Room: retrieval switch shown at the wrong level and in jargon**
`room-context-1280-light.png`, `newtask-1280-light.png`. "Find passages by meaning (sends your documents' text to an embedding provider)" appears in bold (larger than the field labels) in the rail and again in New task before any document exists. The New task help names environment variables (`OPENAI_API_KEY`, `OLLAMA_HOST`) that an end user cannot act on. Nothing shows whether it is available in this install.
Fix: keep it only in the Context card, as "Search long documents by meaning" with a regular-weight label; show it disabled with "Not set up on this server" when no provider exists; move env names to the docs.

**UX-12 Session setup: no mode is selected and nothing shows which task you are setting up**
`setup-nosession-1280-light.png`. The page title is "Session setup" with no task title, brief or attachments. No mode card is selected by default and Start session is active with an empty roster. Mode cards use internal wording ("Raise Hand" for Open Chat).
Fix: show the task title and brief at the top, preselect the recommended mode (Debate), disable Start with a reason ("Choose at least two agents") and describe Open Chat in plain words ("Agents speak when they have something to add").

**UX-13 Session setup, mobile: 13 agent cards come before the roster and the Start button**
`setup-nosession-390-light.png` (2,740 px tall). The roster that the user is building is after the whole catalogue, so after tapping "Add to roster" nothing visible changes. Start session is at the very bottom.
Fix: a sticky bottom bar on mobile: "3 seats, about $1.01 / $5 cap [Start session]" that opens the roster sheet. Add a search or filter over the agent list.

**UX-14 Room: roster names truncate to "A..." and "C..."; model picker crowds out the name**
`setup-warn-1280-light.png`, `setup-build-mode-1280-light.png`. In "Selected roster" each seat shows a 1-letter name followed by an ellipsis because the model select takes the row. The user cannot tell which model belongs to which agent without the avatar-ring. Also axe `label-content-name-mismatch` on room Context buttons (UX-23).
Fix: stack the model select under the name, or give the name priority and shrink the select.

**UX-15 Session setup: budget warning is clear but does not block or guide**
`setup-warn-1280-light.png`. A cap of $0.20 against a $1.01 estimate gives "505% of budget cap", a red bar and a good amber explanation, but Start session stays fully active and the preset buttons do not highlight. Mock GPT shown as a model option with no cost hint.
Fix: add a "Use suggested $X" button in the warning, mark the selected preset, and show per-turn cost in the model dropdown labels so the gateway models are comparable.

**UX-16 New task dialog: mobile footer is out of view and Build is a hidden checkbox**
`newtask-390-dark.png`. At 390 px the dialog body is cut at the viewport; the Cancel and Create task row is not visible without scrolling the dialog. Output type is free text ("Pick one or type your own") with no visible choices.
Fix: pin the dialog footer, show output types as chips (Decision, Plan, List, Document, Code), and reveal the Build repository fields inline when the box is ticked.

**UX-17 Task board: two search boxes that look alike**
`board-1280-light.png`. "Search tasks" (filters the list by title, right side) and "Search what was said in past discussions" (full width, with its own Search button) sit on top of each other. A user typing a keyword in the wrong one gets nothing or the wrong result. The empty state "Nothing matches. Try another filter or search." does not say which.
Fix: one search field with a scope switch ("Tasks / Inside discussions"), or relabel the first "Filter by title" and place it with the filter chips. Make the empty state name the query and offer "Clear search".

**UX-18 Task board: status vocabulary and row actions are inconsistent**
`board-1280-light.png`. "Ready" is shown for a task whose session is created but never started, yet the action is "View last session" and the filter has "Not started" but not "Ready". "Interrupted" and "Failed" offer "View last session" but not "Start again". "More" is plain text with no menu affordance and holds Delete and Archive. On mobile "View last session" wraps to two lines and "New session" is un-boxed text.
Fix: align labels with filters, make the row's primary action match the state (Resume, Retry, Open room), and render More as a kebab button with an accessible name per row.

**UX-19 All pages: the tab title is always "Bayto"**
Checked on `/`, `/services`, `/room/...`, `/welcome`. Several rooms in tabs cannot be told apart, and history entries are all "Bayto".
Fix: set `document.title` from the route (task title for rooms).

## P3

**UX-20 Missing session and missing task: bare red line, no heading, misaligned**
`room-missing-1280-light.png`, `setup-missing-1280-light.png`. "This session doesn't exist, or the link is wrong. Back to tasks" is plain red text at x=23 while the page content elsewhere starts at 59 or 90. axe: no `<h1>` (page-has-heading-one). The generic 404 (`notfound-1280-light.png`) is properly designed; these two should match it.
Fix: reuse the NotFound component with "Session not found".

**UX-21 Sign-in: bare form, native-looking field, disabled button, no help**
`signin-390-light.png`. Shows "This server asks for an access token." and a native-style input with the page focus ring drawn square, plus a grey disabled "Sign in". No password reveal, no hint where the token comes from, and a wrong token's error was not reachable without a token. Page is vertically centred with a lot of dead space and no heading.
Fix: add a heading, helper text ("Set by BAYTO_API_TOKEN on the server"), round the input like other fields, and show an explicit "That token was not accepted" message.

**UX-22 Services page: developer error shown to everyone**
`services-1280-light.png`. "control panel not reachable (502). Run: python3 scripts/bayto-control.py" is the whole page when the control script is down. Nothing is explained about what Services is for, and it is in the main nav next to Tasks.
Fix: explain the page in one line, put a Retry button on the error, and either hide the nav item for non-developers or label it "Developer tools".

**UX-23 Room: icon-like buttons whose accessible name differs from visible text**
axe `label-content-name-mismatch` (serious) on the attachment buttons: visible "Everyone" / "Only ux-designer" but `aria-label` "Who can read <file>" (`room-context-1280-light.png`). Voice-control users saying "click Everyone" fail.
Fix: start the aria-label with the visible text ("Everyone, change who can read <file>").

**UX-24 Small targets in the room rail and header**
Attachment actions, audience links and nav links measure 25 to 30 px tall, under the 44 px target (WCAG 2.5.8 minimum is 24 px; touch guidance is 44 px). The breadcrumb link is 15 px high.
Fix: raise padding on mobile for rail actions and the breadcrumb.

**UX-25 Landing: lazy-loaded screenshot cards render empty; dark hero text**
`landing-1280-light.png`. The four "Seat your agents / Leave with a decision / Or leave with a change / Every task in one place" cards show blank white boxes in a full-page capture (images use `loading="lazy"`); if the images are slow or fail, the page has four empty cards with no placeholder. The video poster frames are tiny and low-detail.
Fix: give the cards an intrinsic background and skeleton, and confirm they load when scrolled.

**UX-26 Room: Jump to latest overlaps content and is not announced**
`room-scrolled-1280-light.png`. The pill floats over the last lines of the synthesis card. It is not an `aria-live` region, and it does not show how many new turns arrived.
Fix: anchor it to the composer edge, show "3 new turns", announce to assistive tech.

**UX-27 Room: moderator summary card is a warning-coloured block with filler text**
`room-failed-1280-light.png`. On failed and interrupted sessions it says "The summary appears after the first turns." in the same amber as a warning, taking more attention than the usage numbers.
Fix: hide the card when there is nothing to show, and use a neutral surface for it.

**UX-28 Change set page: reads well but the key action is below the fold**
`room-build-1280-light.png`. "Ready to review and merge" shows the branch command, stats, tests and review, but "Open pull request" is at the bottom (below Review, Commits, Files), beyond the composer line. The two paragraphs about the repository being left on the branch are dense.
Fix: put the pull request action in the card header next to the status chip, and fold the git switch-back note into a details section.

**UX-29 Setup: Create agent dialog on mobile has no visible permission summary near the button**
`setup-agent-dialog-390-light.png`. The footer text "Add a name, a stance and instructions." sits beside a disabled Create button; the permission note ("Discussion only") is hidden inside the form. Good that it is explained, but a custom agent cannot be given Build permissions, which is not stated.
Fix: say "Custom agents join discussions only; they cannot be Build seats."

**UX-30 Dark mode: amber is used for primary buttons, banners and the disabled Send**
`board-390-dark.png`, `room-tall-context-dark.png`. The amber primary in dark mode matches amber warning banners (paused, ended), so "primary" and "caution" are the same colour. Light mode keeps them apart (navy primary, amber banner).
Fix: choose a distinct dark-mode primary (light neutral or blue) or lower the banner saturation.

**UX-31 Board: finished Build task's list row shows "Change ready" as a pill that looks like "Synthesis ready"**
`board-1280-light.png`. Both are the same amber pill, so a task needing a code review looks the same as a finished discussion.
Fix: make "Change ready" a distinct chip with a branch icon, and sort it above plain results.

## What works well

- Confirm dialogs are specific and safe: Delete explains what goes and offers Archive as the gentler option, with "Keep it" as the default (`room-delete-confirm-390-light.png`).
- Budget handling on setup is honest ("A planning estimate, not a quote", hard cap vs suggested tokens) and the low-cap warning explains the consequence.
- The Build setup shows exactly what each role may run in a table, and the Check repository result is plain ("Working tree is clean").
- The change set card is a strong summary: stats, tests with exit code, reviewer verdict, switch command with Copy.
- Role-restricted attachments are visible in the rail as "Only <role>", and the roster ring plus colour-coded turns make speakers easy to follow in both themes.
- Keyboard basics are in place: skip link, visible amber focus ring, sensible tab order, `aria-pressed` on Add to roster; axe found no contrast violations on any page.
- Status copy for pause ("Your message is saved and the agents see it when you press Resume") and interrupted sessions is clear about what happened to the data.
- The 404 page and the search empty state are friendly, and the landing page explains modes and cost control well.
